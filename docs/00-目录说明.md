## 文档维护规则（2026-10-07 定稿，2026-10-28 适配 v2 布局）

1. **每个 mod 的设计文档放在各 mod 仓的工程目录里**（父夹 `E:\Game\Mod\survivallog-mods\<Mod>\SurvivalLog.<Mod>\DESIGN.md`），
   不与 suite 公共文档混放。12 个 mod 仓：BackpackExpand / CabinetSize / FridgeChill / QuickAction /
   CabinetEverywhere / CabinetBurden / RoleUnlock / RobotSpeed / ModCenter / EndlessGuard / PlanPick / PreDisasterSpeed。
   共享源码说明：suite `ModShared\README.md`（唯一改动源在 suite，`tools\push_modshared.ps1` 推各仓镜像）。
2. **每次迭代改动某 mod，必须同步更新该 mod 仓的 DESIGN.md**（每份文档末尾有"迭代维护清单"，
   列明改动类型对应要更新的章节）。内容要求：结论 + 实证依据（反汇编/dump/运行时验证），不写猜测。
3. 发版机制与渠道分工见 [05-版本管理与发版.md](05-版本管理与发版.md)；
   每版玩家向更新说明——套件线在 suite 根目录 `CHANGELOG.md`（publish.ps1 发版闸门），
   单 mod 线在该 mod 仓工程目录的 CHANGELOG.md（各仓仓内 release.ps1 发版闸门）。
4. **新增 mod 入套件必须接入防盗署名气泡**（2026-10-14 起，发版强制校验，缺接线直接拒发）：
   - csproj 的 Compile ItemGroup 加 `<Compile Include="..\ModShared\WelcomeTip.cs" />`（ModShared 镜像由 push_modshared 下发）；
   - 插件 `Load()` 末尾加一行 `SurvivalLog.ModShared.WelcomeTip.Install(Log);`
   - 机制与文案单源说明见 suite `ModShared\README.md`（GameObject 名去重：装任意一个 mod 即有气泡，装多个只弹一条）。

## 目录树（v2 父夹模型）

```
E:\Game\Mod\survivallog-mods\        ← 父项目夹（非 git 仓）
│
├── suite\                           ← 中枢仓（GitHub 组织 survivallog-mods/survivallog-mods）
│   ├── docs\                        ← 📚 项目文档（本目录，长期维护）
│   │   ├── 00-目录说明.md           本文件
│   │   ├── 01-需求文档.md           功能需求（用户诉求 + 明确不做）
│   │   ├── 02-技术设计.md           架构 / 拆分原语 / API 事实 / 配置项（StackLimit999 历史稿存档）
│   │   ├── 03-教训与红线.md         事故记录 + 红线清单（改码必读）
│   │   ├── 04-版本历史.md           每版改了什么
│   │   ├── 05-版本管理与发版.md     版本号/CHANGELOG/publish.ps1 套件线 + 仓内 release.ps1 单发线
│   │   ├── 06-WebUI调试通道与源码地图.md  DevTools 远程调试 + WebUI 明文源码（UI 类 mod 必读）
│   │   ├── 07-游戏资料库gamekb.md   gamekb 快照 / 兼容核对（游戏更新后必读）
│   │   ├── 08-N网自动发版与更新.md  N网 Upload API 通道：确认门 / 常表 / 红线（发 N网必读）
│   │   └── superpowers\             迁移/开发过程 spec 与 plan 存档（历史记录，不再改写）
│   ├── ModShared\                   共享源码唯一权威（WelcomeTip 等；push_modshared 推 12 仓）
│   ├── installer\                   Inno Setup 安装器（installer.iss）
│   ├── tools\                       🧪 工具链：publish.ps1 / push_modshared.ps1 / gamekb\ / 打包与取证脚本
│   ├── release\                     📦 套件发布产物（构建时生成，不入库）
│   ├── assets\                      发版物料（横幅/截图等，入库）
│   ├── SurvivalLog.ActionProbe\ / ViewportProbe\ / ConfigDumpProbe\   ← 取证探针（绝不发布）
│   ├── SurvivalLog.StackLimit999\ / SurvivalLog.CabinetExpand\        ← 存档 mod（绝不发 Release）
│   └── AGENTS.md / README.md / CHANGELOG.md / version.json（套件号单源）
│
├── <Mod>\                          ← 12 个 mod 仓（各自 git 仓 = 组织仓 = 开发主场）×12
│   ├── SurvivalLog.<Mod>\          ← 工程目录（源码 + csproj + DESIGN.md + CHANGELOG.md）
│   ├── ModShared\                  ← 共享源码镜像（生成物，勿手改）
│   ├── release.ps1                 ← 仓内单发流水线（构建/打包/update.json/tag+Release）
│   └── README.md / LICENSE         ← 玩家文档与许可
│
├── gamekb\                         ← 游戏资料库（本地 only，永不入库）：<日期>_<buildid>\ 快照
├── sdk\dotnet\                     ← 便携 .NET SDK（全部仓共用的构建依赖）
├── thirdparty\                     ← 第三方 N 网 mod 本地参考（禁止转载分发，不入公开仓）
└── 发版物料\                       ← 本地发版物料（不入库）
```

## 游戏侧安装位置（交付物）

```
E:\SteamLibrary\steamapps\common\Survival Log\
├── winhttp.dll                  BepInEx 引导（随发布包）
├── doorstop_config.ini
└── BepInEx\
    ├── core\                    框架
    ├── plugins\SurvivalLog.<Mod>.dll        ← 各 mod 本体（删对应 dll 即卸载该 mod）
    ├── config\com.local.survivallog.<mod>.cfg   ← 各 mod 用户配置
    └── LogOutput.log            mod 日志（排查问题先看这个）
```

存档（与 mod 无关，游戏自己的）：`%USERPROFILE%\AppData\LocalLow\LLS\SLGame\Saves\`
游戏崩溃/报错日志：同目录上级的 `Player.log`
