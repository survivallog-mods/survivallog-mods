# 05 - 版本管理与发版机制

> 2026-10-07 建立。本文档是机制的权威说明（"项目记忆文档"）。

## 渠道分工（定稿）

| 渠道 | 用途 | 内容 |
|---|---|---|
| **GitHub**（组织 `survivallog-mods`：中枢仓 [survivallog-mods/survivallog-mods](https://github.com/survivallog-mods/survivallog-mods) + 12 个 mod 独立仓，公开） | **源码管理 + 版本历史** | 套件 Release 走中枢仓：只打 tag + 更新说明，**不上传任何安装包**；mod Release 走各 mod 仓：附该 mod 的 zip + update.json |
| **百度网盘**（网页版） | **套件安装包分发**（玩家主渠道） | 安装器 exe + 安装说明 + 13 个 zip 分包（Base + 12 mod）；由作者/助手通过网页版上传（同步空间需会员，已弃用） |

> 旧个人仓 `wangk123/survivallog-mods` **弃用中**（已由组织中枢仓接替；横幅+archive 为作者确认后的独立动作，此前请勿再引用/推送）。

## 版本号规则

- **套件线**：suite 根 `version.json` 的 `suite` 字段 = 安装器/中枢仓 tag 线（安装器版本/安装说明共用）。
- **mod 线**：各 mod 版本以**各仓 csproj `<Version>`** 为权威（作者定义）；套件发版时 publish.ps1 拉取各仓后读取并注入安装器。
- **版本号只由作者本人定义**（改 version.json / csproj 或口头指定），助手与脚本只读、绝不自定或自增。
- 版本号自 **v1.0.0** 起在 GitHub 正式管理；此前 1.3.x 为网盘分发时代的历史版本（见 CHANGELOG）。

## 更新说明规则

- 根目录 `CHANGELOG.md`，每版一节（版本号 + 日期 + 新增/修复/调整），面向玩家。
- 发版流水线强制校验：CHANGELOG 里没有对应版本的小节**拒绝发版**。

## 一键发版：`tools\publish.ps1`

```
用法：tools\publish.ps1 [-Yes] [-SkipTest] [-SkipGithub]
```

流程（2026-10-28 多仓编排版）：读 suite version.json 并校验 CHANGELOG → 逐个 12 mod 仓
`git pull --ff-only` + 读该仓 csproj `<Version>` + 各仓仓内 `release.ps1 -PackageOnly`
（自含构建/版本闸门/打包；zip 收回 suite\release\ 并解包成安装器源目录）→ Base 基座包
（`make_base_release.ps1`）→ ISCC 编译安装器（`/DSuiteVer`=套件号、`/DVer<Mod>`=各仓 csproj 版本）→
模板生成【必读】安装说明 → **安装器静默装/卸载回归测试（失败即中止，-SkipTest 跳过）** →
组装网盘上传目录（release\baidu_upload\，15 件 = 安装器+说明+Base zip+12 mod zip）→
（-SkipGithub 跳过）中枢仓 git 提交 + 附注 tag `v<套件号>` + push →
GitHub Release（仅 tag + 更新说明文案，不附安装包）→ 清理旧版本产物。

- 游戏有更新时：先跑 `tools\gamekb\gamekb_sync.ps1`，`modcompat_check` 全绿 + diff 报告过目后才进入发版（详见 [07-游戏资料库gamekb.md](07-游戏资料库gamekb.md) §8）

## 套件线日常发版节奏

1. 改代码，正常 commit/push；
2. **作者定版本号**（改 version.json 或告知助手）；
3. 在 CHANGELOG.md 补该版说明（可由助手代写，版本号必须等作者给定）；
4. 跑 `tools\publish.ps1`；
5. 把 `release\baidu_upload\` 里的文件上传到百度网盘（助手可通过网页版代为操作），更新分享。

## 百度云上传操作

- 同步空间功能需要网盘会员，**不使用**。
- 上传方式：网页版 pan.baidu.com 手动上传，或由助手用浏览器自动化代操作（登录一次后 cookie 保持）。
- publish.ps1 每次发版自动把 安装器 + 安装说明 + 13 zip（Base + 12 mod）组装到 `release\baidu_upload\`，直接整目录上传即可。

## 已踩过的坑（改脚本前必读）

- `git push --follow-tags` 只推**附注**标签：打 tag 必须用 `git tag -a`。
- GitHub Release 资产名不支持中文（改名 API 对中文名返回 200 但静默忽略）；现行方案根本不上传资产，无此问题。
- Git Bash 给 gh.exe 传中文参数会被 MSYS 转码打烂；gh 涉及中文路径时用带 BOM 的 .ps1 文件执行。
- PowerShell 5.1 在 `$ErrorActionPreference='Stop'` 下给原生命令加 `2>&1/2>$null` 可能触发 NativeCommandError：裸调用、看退出码。
- 所有含中文的 .ps1/.iss/.txt 必须 **UTF-8 带 BOM**（编辑后检查是否被剥）。
- 构建 must 用 `sdk\dotnet\dotnet.exe` 便携 SDK（系统 dotnet 是空壳）。
- Base 包必须含 `BepInEx\config\BepInEx.cfg` 且 `[Logging.Disk] Enabled=true`（玩家排障 FAQ 依赖 LogOutput.log）。
- 部署 DLL 到游戏目录前必须关闭游戏（文件占用）。

## 单 mod 发版（GitHub 组织通道，2026-10-28 起）

版本双轨：suite `version.json` 的 `suite` 只管安装器与中枢仓 tag；各 mod 独立版本线 = 该仓 csproj `<Version>`（首轮基线全 v1.7.0）。

日常节奏（仓内一站式，不再经 suite 的 release_mod）：

1. 在该 mod 仓改代码，正常 commit/push；
2. 仓内 `SurvivalLog.<Mod>\CHANGELOG.md` 补该版小节（可由助手代写，版本号等作者给定）；
3. **作者**改该仓 csproj `<Version>`（Plugin.cs Version const 必须一致，release.ps1 会校验）；
4. 仓内跑 `.\release.ps1`（默认询问确认，`-Yes` 跳过）。

- **单发**：在各 mod 仓 clone 内跑 `powershell -File "E:\Game\Mod\survivallog-mods\<Mod>\release.ps1"`——版本闸门（csproj/Plugin.cs 一致 + CHANGELOG 闸门）→ 干净树校验（仅放行 CHANGELOG 脏改动）→ 构建 → 打包（cfg 归一规则不变）→ 生成 update.json（md5 + gamekb 快照版本）→ tag `v<版本>` + GitHub Release（zip + update.json 两资产）；`-PackageOnly` 只到打包为止（套件 publish.ps1 复用）。
- **多仓布局**：组织 `survivallog-mods` 下 12 个 mod 仓为**权威源码仓**（本地 clone 于 `E:\Game\Mod\survivallog-mods\<Mod>`），不再是快照镜像；`tools\push_modshared.ps1` 负责 suite\ModShared → 各仓的单向下行同步（有差异才提交推送，幂等）。
- **在线更新契约**（ModCenter 消费）：`releases/latest` → 资产 `update.json`（`mod/version/asset/md5/gamekb`）→ 校验 md5 → 拉 zip（直连→镜像前缀链回退）→ 已加载 dll 改名交换落盘 → 提示重启。详见 `docs\superpowers\specs\2026-10-28-repo-split-and-online-update-design.md`。
- 套件安装器发版（publish.ps1）产物按各 mod 自身版本命名。
- 旧个人仓 `wangk123/survivallog-mods` 已由组织中枢仓接替（2026-10-28 force push 定形）；旧仓弃用（横幅+archive）为后续作者触发的独立动作。
